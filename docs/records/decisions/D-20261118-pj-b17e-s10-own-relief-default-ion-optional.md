# S10 backdrop defaults to our own LOLA relief; Cesium ion is optional

## Context

`D-7d58` made Cesium Moon (ion asset 2684829) the backdrop, which forces every user to create an ion account, a token and add the asset. pj (2026-11-18): that is too much friction for users, and a view built from our own data is more faithful; the external model's extra resolution matters less because our data will be about as fine once more of it is served.

## Framing

Keep CesiumJS (engine, camera, our overlays) and replace only the ion-hosted terrain, the one piece that needs a token.

## Options considered

1. **A. Another open 3D Moon terrain in CesiumJS**: consequence: none found. Cesium Moon is ion-only; Moon Trek serves imagery, not CesiumJS terrain; a quantized-mesh tileset would have to be generated by us anyway.
2. **B. Our own relief meshed from the LOLA DEMs, drawn in CesiumJS; ion kept as opt-in and fallback** (chosen): consequence: no token by default; the DEMs must be on the machine serving `/terrain`.
3. **C. Rewrite the view in three.js on our DEM**: consequence: a second renderer and a rewrite of overlays and controls for no visual gain over B.
4. **D. Embed a public ion token**: consequence: still an external account, and `D-7d58` forbids shipping a token.

## Decision

**B.** Default backdrop = our LOLA relief via `GET /terrain`; Cesium ion Moon stays as an explicit choice (`?terrain=ion`, "Use Cesium ion") and as automatic fallback when the API has no DEM for the site. Order: own relief, ion with token, 2D panorama (`D-ac74`).

## Rationale

The mask and the relief now come from the same DEMs, so the picture and the score cannot disagree about the horizon. The token stays available for anyone who prefers the textured ion model, for example while the API has no data for a site.

## Checks raised

- `D-671e` provenance: the one-liner and details now say "our LOLA DEM relief" in this mode and keep "Cesium Moon, not our model" in ion mode.
- Ion plan assumptions of `D-7d58` still hold for the opt-in path; the default path no longer touches ion.

## Expected behavior and validation

With no token, the view shows relief whose horizon matches our mask (check: correlation 0.97 against the 5 m Site01 mask, `tests/test_terrain.py`). Wrong if a site with DEMs on disk falls back to 2D, or if the mesh horizon visibly disagrees with the mask line.

## Consequences

- `GET /terrain` (503 `terrain_unavailable` without DEMs); the static demo exports `terrain.json` when DEMs exist.
- Installed apps only get our relief if the DEMs are present; otherwise ion (with token) or 2D.
- `D-7d58` remains true for the ion path; its "ion is the backdrop" part is superseded in effect.
