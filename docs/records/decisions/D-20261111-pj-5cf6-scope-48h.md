# 48h scope and definition of done

## Context

Hackathon window is ~48 hours. Product question (`D-20261111-pj-60ab`) and audience (`D-20261111-pj-ea51`) imply more than a minimal comparator. This decision cuts must / stretch / open / out and what “done” means on Sunday.

## Framing

Prefer an ambitious Sunday bar (must + stretch + a working useful backend) while keeping layer-B physics and native mobile out of the default plan. Track-rule compliance for optional expansions left open.

## Options considered

1. **A — Owner cut**: must = one viz + needs-adapted score + explained thresholds; stretch = local search, global max, friendly UI, other viz; decidable = temperature, dust, trajectories; out = native mobile; done = must+stretch with a backend that works well (useful X,Y,Z).
2. **B — Same cut, done = must only**: success does not require stretch on Sunday.
3. **C — Must also includes local search**: without local search the product is not defendable under `D-60ab`.

## Decision

**A — Owner cut** (done = must + stretch + useful backend with defined X,Y,Z).

## Rationale

Must: one visualization, score adapted to needs, thresholds explained. Stretch: local search, global maximization, friendly UI, remaining visualizations. Decidable (most likely depending on time in the hackathon; left open if time remains or post-hackathon; would need to check track-rule compliance): temperature, dust, trajectory calculation. Out (may be post-hackathon): native mobile app. Done: must and stretch, but the backend really works well and achieves defined results X, Y, Z (essentially: that it is useful).

## Checks raised

- Trying to cover too much and the engine not actually working well → would make this cut wrong.
- Done = must+stretch conflicts with that risk; owner confirmed A anyway.
- Friendly UI is stretch here but default in `D-ea51` → Sunday may ship technical+explainable without “friendly”.
- X,Y,Z undefined until metrics/validation decisions.

## Expected behavior and validation

This choice would be wrong if we tried to cover too much and the engine did not actually work well.

## Consequences

- Metrics decision must define X,Y,Z and the score/threshold scheme.
- Recommender pieces (local + global) are stretch for delivery but part of “done” under this definition — schedule risk.
- Claims must not treat decidable layer-B items as in-scope unless compliance and time allow.
